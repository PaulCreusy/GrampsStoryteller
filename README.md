# GrampsStoryteller

A [Gramps](https://gramps-project.org) tool that writes, in a note attached to a
person (or to many persons at once), the **historical context** of the places and
periods where this person lived. The text is generated by the LLM of your choice from **Wikipedia
excerpts**, which are cited in the note.

**No identifying data leaves Gramps**: the LLM only receives unlabeled years and
places (and, if you enable it, the occupation). It never receives a name, an
identifier, an event type, a relative or a note of your tree.

## Requirements

- Gramps 5.1, 5.2 or 6.0, with Python 3.8 or later.
- Network access to Wikipedia and to the LLM provider.
- An API key for a cloud provider, or a local server (Ollama, LM Studio...).

No extra Python package is needed: the addon only uses the standard library.
If the `keyring` package is available in Gramps' Python, API keys are stored in
the system keyring.

## Installation

Each Gramps version has its own package folder in this repository:

| Gramps | Project URL |
|---|---|
| 6.0 | `https://raw.githubusercontent.com/PaulCreusy/GrampsStoryteller/main/addons/gramps60` |
| 5.2 | `https://raw.githubusercontent.com/PaulCreusy/GrampsStoryteller/main/addons/gramps52` |
| 5.1 | `https://raw.githubusercontent.com/PaulCreusy/GrampsStoryteller/main/addons/gramps51` |

### Gramps 5.2 and 6.0: Addon Manager (recommended)

1. In Gramps, open **Edit ▸ Addon Manager**.
2. Open the **Projects** tab and click **+**.
3. Enter a name (e.g. `GrampsStoryteller`) and the project URL of your Gramps
   version (see the table above).
4. Back in the **Addons** tab, pick **Storyteller: historical context** and click
   **Install**.
5. Restart Gramps. The tool appears in **Tools ▸ Family Tree Processing**.

Updates are then offered by the Addon Manager like those of the official addons.

### Gramps 5.1: update check

Gramps 5.1 checks a single addon repository, so the official one has to be
replaced for a moment:

1. Open **Edit ▸ Preferences ▸ General** and note the **Where to check** URL
   (the official one is
   `https://raw.githubusercontent.com/gramps-project/addons/master/gramps51`).
2. Replace it with the Gramps 5.1 project URL (see the table above) and set
   **What to check** to include new addons.
3. Click **Check for updated addons now**, tick **Storyteller: historical
   context** and click **Install Selected Addons**.
4. Put the official URL back in **Where to check**, then restart Gramps.

Repeat these steps to install a new version.

### Manual installation

Extract `GrampsStoryteller.addon.tgz`, from the `download` folder of your Gramps
version, into the Gramps user plugins directory, then restart Gramps:

| Gramps | Linux | Windows |
|---|---|---|
| 6.0 | `~/.local/share/gramps/gramps60/plugins/` | `%LOCALAPPDATA%\gramps\gramps60\plugins\` |
| 5.2 | `~/.local/share/gramps/gramps52/plugins/` | `%LOCALAPPDATA%\gramps\gramps52\plugins\` |
| 5.1 | `~/.gramps/gramps51/plugins/` | `%APPDATA%\gramps\gramps51\plugins\` |

Gramps 5.2 and 6.0 keep using the 5.1 folder (`~/.gramps` or
`%APPDATA%\gramps`) when it already exists.

## Usage

1. Select a person in the People view.
2. Open **Tools ▸ Family Tree Processing ▸ Storyteller: historical context**.
3. Click **Settings...** once to choose the provider, the model and the API key.
4. Choose the persons to process:
   - the active person;
   - the persons selected in the People view;
   - the active person and their ancestors or descendants, on a number of
     generations;
   - a custom person filter (created with the Person Filter Editor);
   - the whole tree.

   A line under the choice tells how many persons will be processed and how many
   notes will be replaced.
5. **Data sent...** opens a window listing, for each person, the years and
   places that will be sent, and the persons that will be skipped (living,
   private, without usable landmark, or already having a note when "Skip the
   persons who already have a Storyteller note" is ticked). Its "Full request"
   tab fetches the Wikipedia excerpts and shows the exact prompts; nothing is
   sent to the LLM at this step.
6. **Generate** writes the notes. Running it again replaces them. At the end, a
   result window opens: for one person, the note and its warnings; for several
   persons, the list of the persons (with a filter on the problems) and the
   details of the selected one. **Show the result** reopens it.

For several persons, a confirmation shows the number of notes, of LLM requests
and an upper bound of the tokens before anything is sent. Persons with exactly
the same landmarks share one generation. Each note is written in its own undoable
transaction, the batch can be stopped at any time, and it stops by itself after
three failures in a row (e.g. a wrong API key).

## Checking the text

Local checks always run, for free: empty or truncated text, URLs, years that the
excerpts do not contain, unbalanced general knowledge tags. A text that fails a
blocking check is not written.

Two optional checks cost more requests:

- **LLM validation** (off by default): a second request compares the text with
  the excerpts and lists, with an explanation, the statements that are
  unsupported, contradicted, over-interpreted or off-topic.
- **Automatic correction** (off by default, requires the validation): when the
  validation finds problems, the text is rewritten without them and checked
  again. The note receives the corrected text; the window also shows the text
  before the correction. If the correction fails, the initial text is kept.

## What is sent

| Data | Sent to | Notes |
| --- | --- | --- |
| Birth year and place (fallback: baptism) | Wikipedia, LLM | Year only, without label |
| Death year and place (fallback: burial) | Wikipedia, LLM | Year only, without label |
| Occupation | LLM | Only if "Send the occupation" is ticked |
| Postal / INSEE code of the place | nobody | Used locally to find the department, region and historical province |
| Names, IDs, relatives, marriages, notes | nobody | Never read |

Living persons and private persons, events or places are always excluded.

## How the context is sourced

For each place the addon looks for Wikipedia articles from the most local to the
broadest level, because small communes rarely have a detailed history:

1. the commune;
2. its department (from the postal/INSEE code entered in the place **Code**
   field, or from the place hierarchy);
3. the historical province (e.g. Bretagne, Normandie) and, for recent years, the
   current region;
4. the national periods covering the years (e.g. Monarchie de Juillet, Third
   Republic), or the history article of a foreign country.

When the history section of a department, province or country has nothing for
the years, its dedicated article is used instead (e.g. "Histoire de la
Haute-Saône"). Only the paragraphs that match the years are kept; undated
paragraphs are kept only under a heading specific to the period (e.g.
"XIXe siècle", not "XXe et XXIe siècles"). When
the local sources are rich, the LLM may only use outside knowledge for the daily
life paragraph; otherwise it may add well-established general knowledge anywhere.
General knowledge is shown in italics, with a one-line legend. The daily life paragraph is general knowledge as a whole: it is always in italics.

The text has three short paragraphs, from the general to the particular: the
national and regional context, the local context, then the daily life of an
inhabitant (housing, food, work, religion...). Sources are not cited inline: they
are listed at the end of the note.

## Note

The note contains the context, the list of the cited Wikipedia revisions and a
discreet line with the generation date and model. It has the type
"Life story" and the tag `Storyteller`.

## Settings

Settings are stored in `~/.config/grampsstoryteller/settings.json` (Windows:
`%APPDATA%\grampsstoryteller`). Keys are read, in order, from the provider
environment variable (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`,
`MISTRAL_API_KEY`...) or `GRAMPSSTORYTELLER_API_KEY`, the system keyring, then
`credentials.ini` (readable by the owner only). Wikipedia answers and generated
texts are cached in `~/.cache/grampsstoryteller`.

The prompts can be edited in the settings; the variables are `{reperes}`,
`{profession}`, `{sources}`, `{consigne_sources}`, `{langue}`, `{longueur}` and,
for the optional check and correction, `{texte}` and `{problemes}`.

The interface is available in English and French (it follows the language of
Gramps). The language of the generated texts and of the Wikipedia articles is a
separate setting.

## Limits

- The context is only as good as the Wikipedia articles: many small communes
  have no history section, and the text then relies on the department, the
  province and the national periods.
- LLMs can still distort what the excerpts say, especially small local models.
  Read the notes, and use the LLM validation and the automatic correction when
  in doubt. General knowledge is always shown in italics.
- Only French administrative levels (department, province, region) are
  resolved from the place code; abroad, the place hierarchy of the tree is used.
- The years are those of the birth (or baptism) and death (or burial) events;
  other events are not used.

## Development

```
python3 -m pytest tests            # core tests (Gramps tests are skipped)
python3 scripts/i18n.py update     # refresh po/template.pot and po/fr-local.po
python3 scripts/i18n.py check      # list the missing translations
python3 scripts/build_addon.py     # rebuild addons/gramps51, gramps52 and gramps60
```

Interface strings are the literals passed to `_()`. After adding or changing
one, run `scripts/i18n.py update` and translate the new entries of
`po/fr-local.po`; the build compiles them into the archive.

### Release

1. Bump the version in `GrampsStoryteller.gpr.py` and `storyteller/__init__.py`.
2. Run `scripts/i18n.py update`, complete the translations, then
   `scripts/build_addon.py`.
3. Commit, and merge into `main`: the Addon Manager offers the new version to
   the users of the project URL.

The CI checks that the translations are complete and that the committed package
matches the sources.

The Gramps integration tests run when `gramps` is importable, e.g. with the
Gramps sources on `PYTHONPATH` (see `.github/workflows/ci.yml`). The development
plan is in [docs/PLAN.md](docs/PLAN.md).
